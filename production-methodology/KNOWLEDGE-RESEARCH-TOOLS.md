# 知识研究工具与可视化规范

> 用途：将研究中形成的概念、理论、机制和关系组织成可检查、可讨论、可持续更新的知识结构。
>
> 本规范适用于 Agent Mind 的人生系列、哲学研究、Agent 自主性研究及其他长期研究项目。

## 1. 核心原则

研究不能停留在概念罗列。需要明确概念的定义、边界、层级，以及概念之间究竟是什么关系。

**文字负责精确说明，图形负责显露结构，交互页面负责探索复杂关系。**

默认维护两种不同结构：

1. **知识结构地图**：按照概念之间的理论关系组织，允许层级、网状联系、分支和反馈。
2. **观众认知路径**：按照观众理解一个问题所需要经历的认知过程组织，服务于传播和讲解。

二者不能互相替代。知识地图不是视频大纲。

## 2. 相关术语及其边界

| 术语 | 英文 | 适用任务 | 边界 |
|---|---|---|---|
| 概念图 | Concept Map | 表达概念、命题及其关系，常用层级组织 | 重点是有意义的概念关系，不只是节点连线 |
| 概念关系网络图 | Conceptual Network Map | 展示多类型概念之间的网状联系 | 是对图形表达的描述性名称，不应误称为唯一标准化学术方法 |
| 知识图谱 | Knowledge Graph | 以实体、关系和属性组织可查询的结构化知识 | 不等于任何一张看起来像网络的图片 |
| 语义网络 | Semantic Network | 表达概念之间的语义关系 | 重点是语义联系及其表示 |
| 因果图 / 因果关系图 | Causal Diagram | 表达变量之间的因果假设或识别结构 | 相关关系不能自动画成因果关系 |
| 因果回路图 | Causal Loop Diagram | 表达系统中的正反馈、负反馈和循环结构 | 常用于系统动力学；正反馈不等于好，负反馈不等于坏 |
| 系统图 / 系统地图 | Systems Map | 展示系统组成、边界、关系、约束和反馈 | 适合复杂系统整体分析 |
| 流程图 | Flowchart | 展示步骤、决策和流程分支 | 适合程序性顺序，不适合承载全部理论关系 |

**本项目默认采用：概念关系网络图。** 需要层级时加入分组或父子关系；需要解释因果时明确标记因果边；需要展示反馈循环时使用回路结构。不要把这些不同表达任务统称为一张普通“思维导图”。

## 3. 关系必须有类型

每条连线都应标注关系含义。常见关系至少包括：

- **分类关系**：属于、是一种、子类。
- **组成关系**：包含、由……构成、部分—整体。
- **过程关系**：先于、进入、调用、转化为。
- **因果关系**：导致、增加、降低、改变。
- **支持关系**：支持、提供条件、促进、依赖。
- **约束关系**：限制、阻碍、形成瓶颈。
- **反馈关系**：反馈、调节、修正、强化。
- **评价关系**：评价、判断、符合标准。
- **对照关系**：区别于、相反、互补。

不能仅凭两个概念有关联，就把它们放在同一层级；也不能把“属于”“支持”“导致”和“评价”画成同一种连线。

## 4. 层级与网络分开处理

复杂研究通常同时包含两种结构：

- **层级结构**回答：概念属于哪个范畴、处于哪个分析层次？
- **网络结构**回答：不同层级或不同分支的概念之间，存在什么关系？

因此允许跨层连接。不要为了画成整齐的树而删掉真实存在的交叉关系，也不要因为存在交叉关系就抹掉层级区别。

## 5. 因果表达的证据等级

图中出现箭头，不代表因果关系已经得到证实。每条因果边应区分：

1. **已获得经验支持**：有可核验的研究或数据支持。
2. **理论机制解释**：有明确理论推导，但本图不声称已经完成经验验证。
3. **工作假设**：目前用于组织研究的问题或暂定解释，等待进一步检验。
4. **非因果关系**：分类、组成、支持、对照、评价等，不应标成因果。

在图例、节点详情或研究文档中说明这些区别。尤其避免把时间先后、相关性或逻辑依赖直接写成因果。

## 6. 根据研究问题选择表达方式

| 研究问题 | 优先表达方式 |
|---|---|
| 概念有哪些类别、上下位关系是什么？ | 层级分类图 / 概念图 |
| 多个概念之间如何交叉联系？ | 概念关系网络图 |
| 一个结果由哪些因素导致？ | 因果图 |
| 系统如何通过反馈不断变化？ | 因果回路图 / 系统动力图 |
| 一个过程按什么顺序发生？ | 流程图 / 时序图 |
| 观众需要按什么顺序理解？ | 观众认知路径图 |
| 知识需要被机器查询、推理或复用？ | 结构化知识图谱 |

不为视觉效果而画图。只有当图能让关系更清楚、让遗漏更容易被发现，或让用户能够探索不同路径时，才值得采用。

## 7. 标准工作流程

1. **界定研究问题**：明确研究对象、边界和需要解释的现象。
2. **建立文字底稿**：先定义概念，避免在图中用模糊标签代替解释。
3. **区分概念层级**：标出范畴、子类、组成部分、过程环节和结果。
4. **建立关系边**：每条边都写明关系类型及方向。
5. **标注证据状态**：区分事实、理论解释、工作假设和规范性判断。
6. **进行结构审查**：检查是否混淆层级、相关与因果、机制与结果。
7. **选择可视化形式**：根据任务决定使用概念图、网络图、因果图、流程图或组合形式。
8. **制作交互页面**：当节点较多或需要查看详情、筛选关系、切换视图时，使用 HTML/SVG。
9. **回写文字结论**：图中出现的新关系、疑点和修订必须同步记录到 Markdown。
10. **持续维护**：理论变化时更新文字与图，不让图成为过时的装饰品。

## 8. 推荐的双格式资产结构

- **Markdown**：保存定义、论证、证据、边界、未决问题和版本变更。
- **HTML**：展示概念网络、分层、关系边、筛选、节点详情和阅读路径。
- **SVG**：适合静态、清晰、可嵌入文档的关系图。
- **PNG**：适合不支持 SVG 的场景、演示和视频素材；不作为可编辑关系结构的唯一来源。

HTML 页面应尽量采用独立专题目录，避免把所有研究内容塞进单文件或仓库根目录。

## 9. Agent 的主动检查规则

以后进行研究、整理笔记或制作视频时，主动检查：

- [ ] 当前是在建立知识结构，还是设计观众认知路径？
- [ ] 概念是否被错误地放在同一层级？
- [ ] 每条连线是否有明确的语义？
- [ ] 分类、组成、因果、支持、约束、反馈和评价是否区分？
- [ ] 是否把相关关系误写成因果关系？
- [ ] 因果箭头是否标明证据状态？
- [ ] 当前问题是否真的需要网络图，还是层级图、流程图或因果图更合适？
- [ ] 图中的结论是否同步进入 Markdown？
- [ ] 研究发生变化时，是否同步更新图和文字？
- [ ] 是否保留了研究地图与视频认知路径的区别？

**主动提醒规则：** 如果讨论中出现概念罗列、层级混乱、因果关系不清或知识地图与讲解顺序混淆，助手应主动提出使用或修订相应的概念关系图，而不是继续堆叠文字。

## 10. 当前实例

本规范的第一个实际应用是：

- 研究主题：人生机制与增长机制。
- 页面：`series/growth-mechanism/concept-network.html`。
- 表达方式：概念关系网络图 + 层级分组 + 语义关系边 + 反馈关系。
- 注意：页面中的连线表达当前分析框架，不自动代表已经被实证研究证实的因果关系。
