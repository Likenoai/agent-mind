# 人生系列动画制作技术规范

> 状态：项目默认制作规范
> 更新：2026-11-27
> 适用范围：人生系列及《增长机制》相关动态视觉讲解

## 1. 核心技术路线

采用 **SVG 矢量组件 + JavaScript 动画控制 + CSS 视觉与转场** 的混合制作方式。

- **SVG：主要动态视觉载体。** 负责机器结构、机械部件、传送带、管道、水流、液面、粒子、信号路径、数据曲线、坐标轴、标签等可独立控制的元素。
- **JavaScript：动画与时间轴控制器。** 负责物件位置计算、路径跟随、旋转、往复运动、循环、粒子发射、曲线绘制、状态变化、播放/暂停/恢复/重播、时间轴 seek，以及音频时间同步。
- **CSS：视觉表现与场景过渡。** 负责版式、背景、字体、颜色、阴影、圆角、层级、场景淡入淡出和位移等。
- **PNG / WebP：复杂插画与装饰素材。** 适合复杂质感主体、背景、边框、贴纸、阴影等不需要拆解内部动作的对象。

简要原则：**SVG 负责可控结构，JavaScript 负责运动，CSS 负责视觉和转场，PNG/WebP 负责复杂质感。**

## 2. 素材选择规则

### 2.1 优先使用 SVG 的情况

当元素需要独立运动、变形或响应状态时，优先使用原生 SVG 组件：

- 齿轮、活塞、机械臂、传送带及其运动部件；
- 管道、水流、液面、水滴和粒子；
- 反馈信号、路径、箭头、轨迹；
- 数据曲线、坐标轴、数值指示器；
- 需要单独定位、缩放、旋转、遮罩或改变形状的元素。

SVG 不能只作为一张大图使用。应按动作关系拆分成足够细的组件，并保持共享坐标系、锚点和层级关系。

### 2.2 使用 PNG / WebP 的情况

适合：
- 细节复杂、质感丰富、内部不需要单独动画的插画主体；
- 背景纹理、边框、贴纸、装饰物；
- 复杂但整体移动的视觉对象。

图片素材应尽量采用透明背景、统一画布比例、明确视觉中心和安全边距。需要运动的主体应避免把多个无关对象合成在同一张图片里。

### 2.3 混合方案

复杂主体可以使用 PNG/WebP，运动关系由 SVG 路径、遮罩、粒子和 JavaScript 控制。不要为了“全部矢量化”而把复杂插画简化成低精度图形；也不要把需要内部动作的对象整体栅格化。

禁止将 WebP/PNG 简单嵌入 SVG 容器后，就把它当作可编辑的矢量组件。容器可定位图片，但不能自动获得图片内部的独立控制能力。

## 3. 动画实现要求

- 动画必须体现对象之间的运动关系和因果顺序，不以元素淡入淡出代替主体动作。
- 连续过程应使用 requestAnimationFrame 或等效的时间驱动方式；位置应由时间或路径进度计算，避免只依赖上一帧累加，确保暂停、恢复和 seek 后状态一致。
- 沿路径运动优先使用 SVG path 的长度与取点能力（例如 getTotalLength / getPointAtLength）。
- 循环物件必须在完整行程中保持可见；只允许在到达终点、进入明确等待间隔时隐藏，不能在路径中途消失。
- 需要持续运转的设备、流体、信号或粒子应有合理循环节奏；循环间隔可以存在，但不能造成无解释的断流。
- 画面切换必须设计入场、转场和出场。避免大场景长时间交叠造成拥挤；可以采用前一场景退场、后一场景入场的顺序切换。
- 动画必须支持播放、暂停、继续、重新播放；总片嵌入时还要支持总时间轴 seek 和音频同步。
- 画面中的数值若为示意，必须标明是示意，不能暗示为实测数据。

## 4. 镜头级预制流程（Shot-level Preproduction）

1. 锁定原始视听同步脚本中的镜头位置、台词、字幕和动作说明。
2. 明确镜头要表达的概念关系，不新增未经确认的理论结论。
3. 选择视觉隐喻，先做镜头构图和空间布局。
4. 生成复杂插画素材，并拆分可独立控制的动态单元。
5. 建立 SVG 组件、坐标锚点和动画路径。
6. 独立制作 HTML 镜头，完成入场、主体动作、转场和出场。
7. 在目标分辨率下实际播放，检查节奏、对齐、遮挡、裁切、循环和字幕同步。
8. 形成预览图、资源说明、脚本对应文档和验收记录。
9. **用户确认后才嵌入总片。** 未确认的独立镜头不得直接修改总 HTML。
10. 嵌入后由总片音频时间轴驱动动画和字幕；独立镜头的预览字幕和播放控件不能覆盖总片正式时间轴。

## 5. 画面与验收标准

默认使用 16:9、1600×900 作为独立镜头设计基准；其他比例以目标发布容器为准。

每个镜头至少检查：
- 核心概念是否由动作本身表达，而非只靠标签解释；
- SVG 组件颗粒度是否足以支撑所需动作；
- PNG/WebP 是否有透明背景、合理边距、统一视觉中心；
- 元素位置、尺寸、对齐、锚点和层级是否合理；
- 是否存在遮挡、越界、裁切和空间拥挤；
- 主体动作是否连续，是否存在不合理的中途消失；
- 入场、转场、出场是否完整且节奏自然；
- 画面是否与原台词、字幕和脚本边界一致；
- 是否在目标浏览器中实际播放和检查；
- 暂停、恢复、重播、seek 和循环是否正常。

## 6. 概念表达的特别约束

### 边际收益递减 ≠ 瓶颈

- **边际收益递减**：同等额外投入带来的新增产出逐次变小。可以用 +10、+7、+5、+3、+1 或下降曲线表达新增效果递减；不能误画成总存量必然下降。
- **瓶颈 / 容量限制**：核心是处理能力有限、通过速率受限。输入单元与输出单元应保持相同尺寸；视觉重点放在窄口、排队积压、等待时间、通过频率受限，以及可能发生的溢出或资源损耗。**不得用输出物件越来越小或一路向下的视觉趋势来表示瓶颈**，否则会被误读为系统走下坡路或产出自身衰减。

## 7. 可复用组件沉淀

每次独立镜头验收后，优先沉淀通用组件：
- 物件沿 SVG path 运动；
- 连续循环与错峰队列；
- 曲线逐步绘制；
- 粒子沿路径传播；
- 液面遮罩与流入/流出；
- 场景入场、退场与顺序转场；
- 播放控制、时间轴 seek、字幕/音频同步。

组件沉淀应保留参数说明和最小示例，避免后续镜头重复从零实现。

## 8. 资源目录建议

每个独立镜头单独建目录，至少包含：
- 可独立预览的 HTML；
- 可编辑 HTML 与引用的素材（如有外部资源）；
- PNG/WebP 与 SVG 源素材；
- 布局锚点或动画参数 JSON；
- 关键帧/分镜/转场预览；
- 原始脚本对应说明；
- README 与验收记录。

单文件 HTML 若将图片以 data URI 内嵌，也应保留；但可编辑资源应尽量独立归档。版本号与验收状态必须明确区分。
