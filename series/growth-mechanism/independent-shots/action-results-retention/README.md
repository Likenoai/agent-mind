### 视觉方案比较

1. **抽象循环节点：** 容易读懂“重复”，但行动与成果关系过于符号化。
2. **流水线堆积成品：** 动作直观，但容易提前暗示存量累积，混淆 Cue 03 与 Cue 04/05。
3. **同一工作台重复执行，单个即时成果逐次流出：** 保留行动重复与结果产生的因果顺序，不堆叠成品，也不提前表现留存。**V1 采用方案 3。**

### 动作设计

- 工作台的同类制作行动在三个时点重复触发。
- 每次触发都有独立的按压脉冲。
- 每次行动产生一个尺寸一致的即时成果卡片。
- 成果卡片沿同一条路径进入结果区；上一件离场后，下一件才进入，避免形成“存量堆积”的视觉暗示。
- 最后呈现原始关键画面文字：**重复：行动再次发生**。

### 原始脚本（逐字保留）

**画面 / 动作：** 行动节点出现三次脉冲；本次成果从行动沿边流出。

**关键画面文字：** 重复：行动再次发生

**同期讲解：**

> 每一次行动都可能产生结果。完成视频、解决问题、学习知识，都可以产生眼前的成果。但同类行动再次发生，叫重复；重复描述的是行动模式，不是存量或增长速度。

## 制作边界

- 设计基准：1600×900，16:9。
- 技术：SVG/HTML 结构 + JavaScript 时间驱动 + CSS 表现；复杂工作台插画使用 WebP 内嵌素材。
- 独立播放时长严格为 17.005714 秒。
- 播放、暂停、继续、重播、seek 可用；时间状态由绝对时间计算。
- 当前仅完成 Cue 03；Cue 04–06 将在同一视觉系统下分别独立制作。
- 不修改总片 HTML，不更改原始口播和总片时间轴。


## Cue 04｜哪些结果值得留下？

**状态：** V1 已完成首轮实际浏览器播放与交互测试；等待用户视觉验收。未嵌入总片。

- 验证记录：[Cue 04 V1 验证](cue04-validation.md)

### 视觉方案比较

1. 单一仓库/文件柜：容易表现保存，但不容易说明为什么筛选。
2. 单一通过/拒绝闸门：容易把留存误画成简单的好坏判断。
3. 三项判断标准 + 三种留存形式 + 暂不保留的独立离开路径：既展示判断依据，也展示成果可能以不同形式进入未来。**V1 采用方案 3。**

### 动作设计

- 成果物件逐件进入判断装置。
- 「未来使用可能性」「重新获得成本」「遗失的影响」逐项高亮。
- 被保留的成果分别进入内部知识/技能、外部文档/工具、环境流程/条件。
- 暂不保留的成果沿独立路径离开；不进入垃圾桶，不标记为失败。
- 最后呈现原始关键画面文字：**成果产生 → 筛选 → 留存**。

### 原始脚本（逐字保留）

**画面 / 动作：** 结果沿筛选边移动，保留部分继续流入留存；不保留不是失败。

**关键画面文字：** 成果产生 → 筛选 → 留存

**同期讲解：**

> 成果并不都会进入未来。先判断使用可能性、重新获得的成本和遗失的影响，再决定保留哪些成果。内部的知识技能、外部的文档工具、流程或环境条件，都可能成为留存的形式。
