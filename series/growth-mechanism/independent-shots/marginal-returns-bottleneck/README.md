## V5 动画连续性与性能修正

### 1. 减少逐帧 DOM 重建

- V4 每帧清空损耗粒子层并重新创建粒子。
- V5 在初始化时一次性创建 13 组粒子与尾迹（共 26 个 SVG 节点）。
- 每帧只更新既有节点的坐标、半径和透明度；不再调用 `replaceChildren()` 重建粒子层。
- 预缓存滚轮、节拍点、计数器与设备指示灯节点，避免在每帧重复查询。

### 2. 物件交接不再跳位

- 输入、等待、处理、输出物件共用同一套 54×54 SVG 几何。
- 处理开始时：队列物件在 x=610 交接给处理物件；位置和尺寸一致，颜色从橙色平滑过渡为金色。
- 处理完成后：处理物件从 x=765 连续移动到 x=930，并由金色平滑过渡为绿色。
- 输出物件只在处理物件到达 x=930 的同一时刻接手，起点和尺寸完全一致。
- 输出物件继续沿传送带移动至画面右侧离场，不在传送带中途突然消失。

### 3. 设备状态连续

- 齿轮使用单一连续角度函数，不再在“处理/空闲”之间切换旋转速度。
- 等待时钟按镜头时间连续旋转，不再因最早等待物件变化而倒转。
- 处理环在一次处理完成后保持满环；下一轮开始时先平滑归零，再进入下一轮进度。
- 入口闸门在处理开始前预先打开，并平滑关闭。
- 损耗粒子预先创建，循环端点透明度归零，避免可见跳回。

### 4. 输入、处理与输出节拍

- 输入间隔：440ms。
- 处理启动间隔：1280ms。
- 单次处理时长：780ms。
- 处理完成后的离站交接：200ms。
- 输入物件进入队列槽位：150px 路程、360ms。
- 输出离场行程：3200ms。
- 5.4 秒子镜头结束时：12 件到达、4 件完成放行、8 件等待。
- 以上均为动画内部示意参数，不是现实测量数据。
